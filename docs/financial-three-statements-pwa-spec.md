# 财务三表分析器 PWA Spec

版本：v0.1  
日期：2026-05-13  
状态：开发前需求基线

## 1. Problem Statement

非财务用户在评估一家外部公司时，通常只能拿到财务报表 PDF，但他们很难理解资产负债表、损益表、现金流量表之间的关系，也难以判断公司盈利质量、现金流质量和潜在财务风险。

本产品要解决的问题是：

让非财务用户通过上传财务三表 PDF，在较短时间内获得一份通俗、可解释、偏投资分析视角的财务健康报告，帮助他们判断公司是否值得进一步研究，同时辅助理解关键财务指标。

核心用户不是会计或专业财务人员，而是需要看懂财务结果、评估外部公司、学习理解财务报表的普通商业用户。

## 2. Proposed Solution

开发一个桌面端优先的 PWA 财务三表分析器。

用户凭激活码进入系统，创建分析项目，上传资产负债表、损益表、现金流量表 PDF。系统在后端解析 PDF，将数据映射到标准三表科目，用户可逐行查看、编辑和确认。确认后，系统计算 10-20 个关键财务指标，结合用户手动选择的粗行业基准，生成财务健康评分、评级、风险提示和 AI 自然语言分析，最终导出 PDF 报告。

产品采用分层展示：

1. 先给综合评分、评级和核心结论。
2. 再展示盈利质量、现金流质量等重点风险。
3. 然后展示关键指标、行业对比、扣分项和 AI 调整原因。
4. 学习模式中展示指标公式和解释。
5. PDF 报告以投资分析型为主，学习解释为辅助。

## 3. Core User Flow

1. 用户打开 PWA。
2. 系统要求输入激活码。
3. 后端验证激活码有效期和同时在线会话数。
4. 验证通过后进入项目列表或首次向导。
5. 用户选择语言、会计准则、行业。
6. 用户上传三张报表 PDF，或分别上传三表文件。
7. 后端解析电子 PDF。
8. 系统自动识别币种和金额单位，失败时允许手动选择。
9. 系统将识别结果映射到标准三表科目。
10. 用户逐行查看、编辑标准科目数据，允许空值和 0 值。
11. 用户确认“分析结果以确认后的数据为准”。
12. 系统计算指标、基础评分和行业对比。
13. AI 根据结构化财务数据和指标生成分析文字，并在最多上下 10 分范围内调整评分。
14. 系统展示分析结果。
15. 用户导出 PDF 报告。
16. 报告生成完成后，服务器删除原始 PDF 和明细三表数据。
17. 云端只保存历史项目摘要，不保存 PDF 报告。

## 4. Functional Requirements

### 4.1 激活码授权

- 产品以激活码作为唯一授权身份。
- 不做账号密码体系。
- 激活码采用时间订阅权限。
- 进入 PWA 时必须先验证激活码。
- 激活码不绑定设备。
- 每个激活码最多允许 2 个同时在线会话。
- 2 个同时在线会话用于覆盖客户先在手机端激活试用、再切换到电脑端正式使用的场景。
- 激活码过期后立即删除该激活码下的历史摘要。

### 4.2 项目与历史

历史项目只保存摘要：

- 公司名称或项目名称；
- 行业；
- 报告期间；
- 评分；
- 评级；
- 主要风险；
- 生成时间。

历史项目不保存：

- 原始 PDF；
- 完整三表明细；
- 生成后的 PDF 报告；
- 完整分析正文。

用户下次进入只能看到项目卡片摘要，不能查看完整报告，也不能重新导出 PDF。用户可以删除单个历史项目，也可以清空全部历史项目。

### 4.3 报表上传与解析

第一版支持：

- 常见审计报告/年报中的三表电子 PDF；
- 三张报表分别上传；
- 中文和英文报表；
- 中国企业会计准则和 IFRS；
- 单期分析和两期对比。

第一版暂不支持扫描件、拍照件、影印 PDF 的 OCR 识别。

PDF 上传到后端解析，原始 PDF 临时保存到报告生成完成，随后立即删除。

解析失败或不完整时，系统展示已识别的部分数据，用户可补全和修正后继续。

### 4.4 标准科目编辑

系统需要内置两套标准科目体系：

- 中国企业会计准则常见三表科目；
- IFRS 常见三表科目。

用户可以按标准三表科目逐行编辑数据。

编辑规则：

- 允许空值；
- 允许 0 值；
- 不要求完整性检查；
- 分析前必须由用户确认数据；
- 系统提示分析结果以用户确认后的数据为准。

### 4.5 币种与单位

系统需要自动识别币种，支持：

- CNY；
- USD；
- HKD；
- EUR；
- GBP；
- JPY；
- SGD；
- AUD；
- KRW；
- TWD。

识别失败时允许用户手动选择。

系统需要自动识别金额单位，例如元、千元、万元、百万元等。识别失败时允许用户手动选择。

两期对比时：

- 支持两期单位不同，系统自动换算；
- 不支持两期币种不同；
- 若币种不同，提示用户修正。

### 4.6 财务分析能力

分析维度全部纳入，但 MVP 核心优先级为：

1. 盈利能力；
2. 现金流质量；
3. 偿债能力；
4. 运营效率；
5. 成长性/两期变化；
6. 财务结构与稳定性。

风险提示重点偏向：

1. 盈利质量风险；
2. 现金流风险。

其他风险也展示，但排序靠后：

- 偿债风险；
- 应收/存货风险；
- 财务异常波动风险；
- 报表勾稽风险。

关键指标数量控制在 10-20 个。

指标公式只在学习模式中显示。

### 4.7 评分与评级

评分采用“规则分 + AI 调整分”。

基础规则分由以下因素计算：

- 指标表现；
- 行业基准；
- 维度权重；
- 风险扣分项。

AI 可以在基础分上进行有限调整：

- 最多上调 10 分；
- 最多下调 10 分；
- 必须展示调整原因。

最终展示：

- 综合评分；
- 评级；
- 维度得分；
- 权重；
- 关键扣分项；
- AI 调整原因。

评级形式采用“综合评分 + 评级”，例如：

- 82 分；
- A 级；
- 结论：值得进一步研究。

AI 可以输出明确投资评级，但必须包含免责声明，说明不构成证券投资建议、买卖建议、授信建议、审计意见或法律意见。

### 4.8 AI 分析

系统需要调用国内大模型优先。

AI 输入内容：

- 结构化财务数据；
- 计算后的关键指标；
- 行业信息；
- 单期或两期对比结果；
- 风险项；
- 必要上下文。

AI 不接收：

- 原始 PDF 文件；
- 非必要敏感文件；
- 生成后的 PDF 报告文件。

隐私说明中必须明确告知用户：系统会将结构化财务数据和指标发送给第三方 AI 服务用于生成分析，但不会发送原始 PDF。

### 4.9 行业基准

用户手动选择粗行业。

第一版行业分类采用粗粒度，例如：

- 制造业；
- 零售业；
- 房地产；
- 互联网/软件；
- 金融；
- 建筑；
- 医药；
- 能源；
- 其他。

后台可配置行业基准、评分权重、AI 提示词和免责声明。

### 4.10 报告展示与导出

报告导出格式：PDF。

PDF 报告风格：

- 投资分析型为主；
- 学习解释型为辅助。

PDF 报告包含：

- 综合评分和评级；
- 核心结论；
- 盈利质量分析；
- 现金流质量分析；
- 主要风险清单；
- 关键指标；
- 少量关键科目；
- 行业基准对比；
- 关键扣分项；
- AI 调整原因；
- 下一步核查建议；
- 免责声明。

PDF 报告不展示完整三张财务报表。

生成后的 PDF 不保存到云端，用户需要当次及时下载。下次进入无法重新查看或下载该 PDF。

### 4.11 后台管理系统

第一版需要后台管理系统，但范围控制在：

1. 激活码管理：
   - 创建激活码；
   - 批量生成激活码；
   - 启用/停用；
   - 设置有效期。

2. 配置管理：
   - 行业基准；
   - 评分权重；
   - AI API 配置（DeepSeek API Key、模型、接口地址、启用状态等）；
   - AI 提示词；
   - 免责声明。

后台管理端必须与客户前台客户端分离。正式交付给客户的 PWA 只提供前台客户端入口，不能暴露后台管理入口、后台页面或后台接口令牌。后台管理端只供项目方在服务器后台使用。

AI API Key 等敏感配置必须在服务器后台统一配置和保存。本地开发环境中填写的 Key 仅用于本机调试，不视为正式生产配置，不能作为服务器上线后的配置来源。

当前实现约定：

- 客户前台入口为 `index.html`，只包含激活、上传、确认、分析结果和 PDF 下载流程。
- 后台管理入口为 `admin.html`，用于激活码管理、行业基准、评分权重、AI 提示词、AI API 和免责声明配置。
- 正式部署时，`admin.html` 必须放在独立后台入口下，并通过服务器侧鉴权、Nginx 规则、IP 白名单或等效机制保护；不得把该入口发给客户。

第一版后台不做：

- 使用日志管理；
- 在线会话管理；
- 历史摘要管理。

## 5. Technical Constraints

- PWA 以桌面电脑为主要目标设备。
- 不做专门的手机端 UI 适配。手机浏览器可以直接打开电脑端网页，但产品设计、测试和售后引导均以电脑端使用为主。
- 由于三表上传、人工校对和 PDF 报告下载在手机端操作不便，正式使用建议客户在电脑端浏览器完成。
- 不要求完整离线使用，上传、解析、AI 分析、激活码验证和报告生成均需要联网。
- 服务器部署在腾讯云轻量服务器。
- 正式部署时必须区分客户前台客户端与后台管理端：客户只能访问前台 PWA；后台管理端应使用独立入口、独立鉴权和服务器侧访问控制。
- 技术栈按服务器环境选择稳妥方案，不强制指定框架。
- 后端负责 PDF 解析、指标计算、AI 调用、PDF 报告生成、激活码验证和数据清理。
- 前端负责向导流程、项目列表、数据编辑、结果展示、学习模式和报告下载。
- AI 大模型国内供应商优先。
- AI API Key、模型、接口地址、提示词和评分调整范围均由服务器后台配置；不得打包进客户前台代码，不得通过公共配置接口返回。
- 系统不接入股票代码、行情、市盈率、市净率、估值等市场数据。
- 云端只保存历史摘要，不保存原始 PDF、完整三表明细或生成后的 PDF 报告。
- 用户隐私说明必须明确写清楚保存什么、不保存什么、发送给 AI 的数据范围。

## 6. Non-goals

第一版明确不做：

- 不支持扫描件/拍照 PDF 的 OCR 识别。
- 不做多于两期的长期趋势分析。
- 不做用户账号密码体系，只以激活码作为授权身份。
- 不做股票行情、估值、市盈率、市净率等市场数据分析。
- 不做专业审计、法律、税务或授信结论。
- 不保存原始 PDF、完整三表明细、生成后的 PDF 报告。
- 不做网页报告分享链接。
- 不做 Excel、Word、Markdown 导出。
- 不支持完整离线使用。
- 不做后台使用日志、会话管理、历史摘要管理。
- 不保证系统结论可替代专业财务尽调或投资决策。

## 7. Success Criteria

第一版成功标准：

1. 非财务用户可以在 10 分钟内完成上传、确认数据、生成分析和下载 PDF 报告。
2. 报告能够清楚回答：
   - 公司盈利质量如何；
   - 现金流质量如何；
   - 主要财务风险是什么；
   - 是否值得进一步研究。
3. 关键指标计算准确，评分构成可解释。
4. 用户能看到维度得分、权重、扣分项和 AI 调整原因。
5. 常见审计报告/年报电子 PDF 的三表识别成功率目标达到 85% 以上。
6. 即使 PDF 识别不完整，用户也能进入人工编辑补全流程。
7. PDF 解析失败时，系统能清楚提示哪些内容没识别，以及用户下一步如何补救。
8. 激活码订阅、有效期验证和 2 个同时在线会话限制稳定可靠。
9. 报告生成后，原始 PDF 和三表明细数据能按规则删除。
10. 用户清楚知道系统保存什么、不保存什么，以及哪些数据会发送给 AI。
